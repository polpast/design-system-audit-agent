Design System Audit Agent

An agent reads a component library and proposes what to keep, merge, deprecate or update. It can't change anything on its own: every proposal waits for a person to approve it.

Propose, never apply

The agent's only write tool is "propose a change". Applying happens on approval by a person, and every approval can be undone.

Confidence is shown, not hidden

Each proposal carries high, medium or low confidence. Low-confidence proposals say what would settle the question.

Failures are visible

Failed lookups appear in the step log in red, and the agent recovers from them (a misspelled component name, for example) instead of guessing silently.

Rejections teach the next turn

When you reject a proposal, your reason is passed to the agent with your next message so it doesn't propose the same thing again.
